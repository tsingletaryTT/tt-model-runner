Launch Mode

tt-inference-server supports two modes. Which should the GUI cover?

A

Docker Server only

Runs run.py --docker-server — pulls/uses the official ghcr.io Docker image, manages the container lifecycle. This is the standard production path. Simpler to manage: image handles all deps.

Pros

  • Standard deployment path
  • Image handles all deps
  • Container logs via docker logs

Cons

  • Requires Docker
  • Slower first-run (image pull)
B

Docker + Local Server

Covers both --docker-server and --local-server. Local mode requires a pre-built TT-Metal environment and manual venv paths.

Pros

  • Covers all deployment paths
  • Devs using local builds benefit

Cons

  • Local mode needs extra path inputs (TT_METAL_HOME, vllm_dir)
  • More UI complexity
C

Docker primary, Local as advanced

Docker is the default UX. Local server is accessible but tucked into an "Advanced" section with appropriate warnings.

Pros

  • Clean default path
  • Doesn't lock out local devs

Cons

  • Local mode still needs its UI built
